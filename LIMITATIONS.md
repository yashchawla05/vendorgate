# Limitations and next steps

What this demo deliberately does not do, and what we would do next with more time.

## Verification depth
| Limitation | Why | Next step |
|---|---|---|
| GST registry and bank account verification are **simulated** | Real lookups need paid or credentialed providers (GSTN-authorised GSPs, bank-verification APIs) | Implement `RegistryClient` against a provider; cache responses; add timeouts and retries; keep the simulated client for tests |
| PAN, CIN and Companies House numbers are format-checked only | No free official verification API | PAN verification via an ITD-authorised provider; Companies House public API for UK companies |
| UK bank details: no modulus checking | Vocalink tables change several times a year | Add the Vocalink valacdos/scsubtab tables with a refresh job |
| Sanctions: US OFAC lists only, name-only matching | Free, public, verifiable source for the demo | Add UN, EU, UK HMT and Indian MHA lists; use DOB, country and address to disambiguate; refresh the snapshot daily, not manually |
| No expiry or validity checks on certificates | Supported documents carry no expiry | Add rules for document types that do (trade licences, insurance certificates) |

## Document understanding
- The offline extractor reaches 100% on text-layer synthetic documents (see EVAL.md) because it is written against
  their label wording. **Real documents vary far more.** That is exactly why the LLM provider exists. Its accuracy
  on real, anonymised documents is the most important thing to measure next.
- LLM confidences are self-reported. They should be calibrated against an eval set; the threshold (0.8) is an
  assumption.
- Only the first 4 pages of a document are read (cost guard).
- The prompt-injection detector is pattern-based and reads text layers. Text injected inside an *image* is caught
  only if the LLM flags it (`suspicious_instructions`). In both cases the outcome cannot change, because the LLM output
  has no decision field.

## Platform
- **SQLite on an ephemeral disk:** on Streamlit Community Cloud the database resets when the app restarts or sleeps
  (it re-seeds itself). Next: managed Postgres (Neon or Supabase) behind the same `core/db.py` functions.
- **No authentication:** anyone with the URL can open the Reviewer Console. The vendor resubmission page is protected
  only by its token. Next: SSO for reviewers, roles (reviewer vs approver), and four-eyes approval for overrides.
- **Runs in the request:** the pipeline runs inside the user's Streamlit session. A slow LLM call blocks that page
  (not other users). Next: a job queue with a worker, the UI subscribing to stage events.
- **Email:** outbound only (simulated by default). Next: inbound parsing of vendor replies into the audit trail;
  delivery status webhooks.

## Data and evaluation
- All data is synthetic, generated by one script, so layouts and names are less diverse than reality.
- Name normalisation is English-centric. Transliterated Indian names, initials ("R K") and honorifics need more
  rules or a model.
- The "time saved" KPI rests on an assumed 45 minutes per manual review.
- **Gemini was measured live; Claude was not.** With a real Gemini key (2026-11-03, `gemini-3.5-flash-lite`) every
  scenario produced its expected outcome and the eval read 110/110 document types and 445/445 fields correctly
  (EVAL.md). The first live eval found 2 US bank-letter dates read day-first; dates are now copied verbatim and
  converted in code (ASSUMPTIONS.md). The synthetic documents are clean, so 100% here does not predict accuracy on
  real, messy uploads. The Claude path is unit-tested against a mocked API only; run
  `python scripts/smoke_test.py --provider anthropic` with a key to measure it.
- **Model confidence is not calibrated.** In the first live run Gemini reported 0.95-0.99 confidence on the two dates
  it got wrong, so the 0.8 threshold catches unreadable documents, not confident mistakes. Cross-checks (checksums,
  form vs document, freshness rules) are what catch those.
- **Gemini free tier:** about 10 requests per minute and 500 per day for Flash-Lite, shared by everyone using the
  deployed app. A run with many documents pauses to stay under the limit; when the daily quota is gone, document
  reading degrades and outcomes go PENDING until it resets (midnight Pacific time). Free-tier inputs may be used by
  Google to improve its products, which is acceptable only because all data here is synthetic.
